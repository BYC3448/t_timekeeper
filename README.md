## 최종적으로 해결한 문제

교사는 하루에도 수십 건의 공문·업무지시를 카카오톡·이메일·인쇄물로 받습니다. 너무 여러 매체에서 업무들이 쏟아지기 때문에 이 것들을 한 화면에서 모아서 한 번에 보여줍니다.  마감일을 하나씩 읽어 캘린더에 옮겨 적고, 선행 과제를 역산해서 할 일 목록을 만드는 데 매일 적지 않은 시간이 소모됩니다.

### 어떻게 풀었나요?

공문 이미지나 텍스트, 한글파일을 앱에 붙여넣으면 AI가 마감일·카테고리·선행 할 일을 뽑아 확인 대기 상태로 보여줍니다. 교사는 자동 분석 결과를 검토하고 확정만 하면 됩니다.

## 핵심 기능

- **일정 추출**: 이미지, 한글파일, pdf , 텍스트 를 읽고 일정을 뽑아냄
- **일정 저장**: 마감은 캘린더에 저장하고 할일 날짜 역산해서 오늘 날짜에 보여줌 
- **던져넣은 파일 원문 바로 확인**: 던져넣은 파일을 다시 찾아 헤매지 않도록 원문 바로 보여줌.
- **학사 일정 및 개인시간표 파싱 저장**: 초기 설정으로 학사 일정 및 개인 시간표 이미지 읽고 일정 자동 저장 
- **캘린더와 오늘 대시보드 분리**: '오늘' 대시보드 로 오늘의 모든 일 한 페이지에서 확인 가능하도록. 

## 사용 흐름과 사용 방법

1. 공문, 메신저, 카톡 메시지 등을 한글파일 통째로 또는 스크린샷 이미지 등으로 던져 넣는다. 
2. 파일 파싱하여 일정 내용과 날짜 뽑음. 
3. 마감일은 캘린더에만 저장, 할일 날짜 역산하여 해당 날짜부터 오늘 할 일에 보이도록 저장 
4. 할일 옆에 아이콘 클릭하면 원문 볼 수 있음. 
5. 완료한 할일은 지울 수 있음. 
6. (첫단계) 초기 설정에서 시간표, 학사일정 등록 가능 

- 사용 환경: PC웹, 모바일 웹
- 사용 조건: 계정업시 무료로 사용할 수 있어요.

## 기술 스택과 실행 방법

- **화면**: svelte 프레임 워크
- **서버·백엔드**: firebase  활용해서 여러 기기 동시 사용 가능하도록 하려고 했으나 구현 못함.
- **AI**: 클로드 코드, 안티그래비티
- **저장소**: 깃허브
- **배포**: vercel

### 폴더 구조

```text
rc/
  components/     화면 컴포넌트 (설정, 캘린더, AI 검토 모달 등)
  lib/            데이터 저장, Gemini/Upstage 연동, 타입 정의
  routes/         페이지 단위 화면 (오늘, 캘린더)
  widget/         위젯(팝업) 전용 화면과 컴포넌트
```

## 교육 현장에서 사용할 때의 주의사항

- **개인정보 처리 여부**: 처리하지 않음
- **예상되는 위험**: 이름과 업무 내역이 한 화면에서 연결되면 어떤 교사가 무슨 일을 얼마나 맡고 있는지 그대로 드러나고, 이 기록이 업무량 비교나 평가 자료로 전용될 수 있습니다. 학생 이름이나 상담 내용이 자유 입력란에 들어가는 경우 마스킹만으로는 걸러지지 않을 수 있습니다.
- **위험을 줄이려고 한 일**: 학생 관련 정보에 마스킹 기능을 적용했습니다. 다만 마스킹은 이미 들어온 정보를 가리는 방식이라, 애초에 입력되지 않도록 막는 편이 안전하다고 판단해 입력 단계 차단을 검토 중입니다.
- **멈춤 기준**: 마스킹을 거친 뒤에도 학생 개인을 알아볼 수 있는 기록이 남는 것이 확인되면 중단합니다. 교사 업무 기록이 본인 동의 없이 다른 목적으로 조회된 정황이 확인되어도 중단합니다.
- **검증 방법**: 가상의 요청 목록으로 입력 테스트를 하고, 자유 입력란에 학생 이름과 학번을 일부러 넣어 저장과 표시 결과를 확인합니다. 동료 교사 몇 명에게 화면을 보여주고 본인 업무가 어디까지 드러난다고 느끼는지 물어봅니다.

### 입력·전송·저장 정보

- 공문 내용, 메신저 캡처 이미지, 일정 관련 텍스트) — 교사 본인 (붙여넣기·드래그앤드롭·직접 입력) —  AI 분석 시 Google Gemini API로 전송, HWP 파일은 Upstage Document Parse API로 전송. 전송 전 전화번호·주민등록번호는 자동 마스킹 처리(기본 활성화, 설정에서 조절 가능)
- API 키 (Gemini · Upstage · Firebase) — Gemini API 키, Upstage API 키, Firebase 설정값 — 해당 서비스 인증 목적으로만 각 API 호출 시 사용, 제3자에게 전송하지 않음

### 교육적 태도 점검

- 평가·추천·피드백을 프로그램이 대신 확정하지 않게 했나요?: 원래 그렇게 했어요 (타임키퍼는 학생 평가·성적·추천서를 생성하지 않아요. AI는 공문·메신저에서 일정과 할 일만 추출할 뿐, 평가나 피드백 문구를 만들지 않아요.)
- 학생이나 교사의 생각을 대신하지 않게 했나요?: 원래 그렇게 했어요 (AI는 일정·To-Do 항목만 추출·정리하고, "내 담당 일정인지(isMine)"까지 자동 판단해 미리 체크해두긴 하지만, 교사가 "AI 파싱 검토 모달"에서 직접 확인하고 최종 확정해야 캘린더에 등록돼요. 교사의 판단·의견을 AI가 대신 만들어내지 않아요.)
- 저장·전달·제출 전에 사람이 확인할 수 있나요?: 원래 그렇게 했어요 (공문·캡처를 분석하면 바로 저장되지 않고 "AI 파싱 검토 및 교사 최종 확정 모달"을 거쳐 교사가 직접 확인·수정한 뒤 저장 버튼을 눌러야 반영돼요. (단, 시간표는 감지 시 자동 등록되므로 등록 후 확인 안내 문구가 함께 떠요 — 이 부분은 사전 확인이 아니라 사후 확인이라 다른 항목과 다르니, 시간표 자동 등록 전에도 확인 단계를 넣을지 검토가 필요해요.))
- 기기·계정·조작 문제로 참여에서 빠지는 사람이 없게 했나요?: 우리 프로그램엔 해당 없어요 (타임키퍼는 교사 개인이 혼자 쓰는 업무 도구예요. 여러 학생·교사가 함께 참여하거나 특정 기기·계정이 없으면 배제되는 구조가 아니라서 해당 없음이 맞아요.)
